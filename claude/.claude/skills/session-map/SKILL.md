# session-map

会話の結論を、忘れても三十秒で入口に戻れる一枚にする。読み物ではなく、搭載するための設計図。

## 書くこと（この順）

1. 何を解くのか。問題と定義を結論ファーストで。
2. 用語。会話で使った抽象語を、具体例か機械が読める値で言い直す。読者が「分からない」と言った言葉は必ず入れる。
3. 決めたこと。層、規格、置き場所、判定の流れのように、そのまま仕組みに写せる形で。
4. 今ある部品と候補。候補には「二度やったら入れる」と明記し、層（hook / スクリプト / スキル / ルール）を付ける。
5. やらないこと。

## 守ること

- essence の原則に従う。一文一義、抽象語で押さない、会話に無い事実を足さない。
- 一枚。節は十まで。表と短い箇条書きを使い、散文は結論と理由だけ。
- 図は mermaid。ノードとエッジのラベルはダブルクォートで囲む。
- Artifact ツールがあれば Artifact として公開する。無ければ `Atlas/Learn/<YYYY-MM-DD HHmm> <日本語タイトル>.html` に保存し、`open` で開く。
