# HTML 品質向上（html-quality）

技術文書・設計資料系の HTML を、初見の読者が迷わず読める品質に上げる。

## 手順

1. `$essence` を読み、その原則を適用する
2. 下記の HTML 固有チェックリストでレビューする。各項目に pass / fail / **N/A**（該当する内容が資料にない）を付ける
3. fail を**読者への影響が大きい順**に修正する（承認待ち不要）
4. 修正後に再レビューし、全項目 pass、または fail に理由が付いた状態にする

## チェックリスト

品質の**下限**を守るためのもの。表現・構成は固定せず、より良い形があれば自由に改善する。

### A. HTML 構造・妥当性

- [ ] 見出し階層が正しい（`h1 → h2 → h3`、飛びがない）
- [ ] タグが正しく閉じられている
- [ ] 本文の事実（ファイルパス・API 名・設定値など）が実コードで裏取りされている
- [ ] 外部ライブラリ（シンタックスハイライト等）が DOM 読み込み完了後に初期化されている

### B. 図解・視覚化

- [ ] 図は Mermaid や UML 等の標準図法で描かれている（手書きテキスト図・矢印の羅列にしない）
- [ ] 図はラベル付きで、図だけ読んで構造が分かる
- [ ] 変更前後のコード対比は diff 表示（追加=緑、削除=赤）で色分けする。変更後のみだと評価不能
- [ ] 削除行に取り消し線を付けない（コードが読めなくなる）
- [ ] コードブロックは視認性の高いスタイル（ダーク背景・等幅フォント）

### C. センス（AI 臭さを避ける）

**配色**:
- [ ] 青〜紫のグラデーション（ヒーロー・ヘッダー）を使っていない
- [ ] 主要色が AI デフォルトの青域（#3B82F6〜#6366F1 等）でない。アースカラー・ウォームニュートラル・ミュートな彩度を検討する
- [ ] 背景が gray-50（#F9FAFB）でない
- [ ] 配色が一貫している（アクセント色は1〜2色。推奨・警告の意味づけが統一され、色だけでなくラベルでも区別できる）

**タイポグラフィ**:
- [ ] フォントサイズ・字間・行間を内容に合わせている（Inter / system-ui だけに頼らない）
- [ ] フォントサイズ・太字の階層が統一されている
- [ ] `line-height` / セクション間 `margin` / `padding` が CSS で明示されている
- [ ] 本文の行長が読める幅に収まっている（コンテナに `max-width`）

**レイアウト**:
- [ ] 角丸8px以上のカードが並んでいない（余白と罫線で構造を作る）
- [ ] 同一のカードグリッド（3列等）でない。非対称・変化のあるレイアウトを検討する
- [ ] モバイルで崩れない（`viewport` meta、固定 px 幅なし、グリッド折り返し指定あり、コードブロックは `overflow-x: auto` でページ全体を横スクロールさせない）
- [ ] 過剰な装飾がない（情報を伝えるための装飾だけ）

**アクセシビリティ**:
- [ ] カスタム `::selection` / `:focus-visible` / `prefers-reduced-motion` がある
- [ ] 文字と背景のコントラストが十分（本文・キャプション・コード内の文字が薄色で読みにくい箇所がない）

## 修正の優先度

1. **読者が誤った判断をするリスク**（矛盾・事実誤認・結論と本文の不一致）— 最優先
2. **読めないリスク**（構造崩れ・自己完結性欠如・情報過多）— 次
3. **読みにくさ**（長文・図解不足・センス）— 最後

修正はファイルを直接編集し、ブラウザで表示して確認する。
