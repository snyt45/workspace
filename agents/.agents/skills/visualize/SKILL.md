# Visualize

絵が居場所を得るのは、言葉が示せないものを示すときだけ — 形、構造、方向、関係、幾何。このスキルはそのような**1枚**の絵を作り、それが**正しい**ことを保証し（makerがレンダリングして見てから返す）、レッスンの中に Obsidian `md-log` ファイル内で描画される形で落とす。

あなたは**クリエイティブディレクター**。正確なアイデアと、それを運ぶ最小要素を決める。**makerサブエージェント**（herdr経由）が執筆・レンダリング・目視検証・保存を行い、ファイル名を返す。あなたは返されたファイル名を自分のレスポンスに埋め込む。

## いつ可視化するか（いつしないか）

この教育システムは**学習者の頭の中に依存グラフ** — 根に公理、それにぶら下がる派生事実 — を築く。ビジュアルが強力なのは、まさにその構造（または幾何）を可視化するとき:

- アイデアが**構造や関係**のとき: 依存関係、部品と矢印を持つシステム、フロー/パイプライン、交換のシーケンス、状態機械、木/階層、比較、包含（中 vs 外）。
- アイデアが**空間的・幾何的**のとき: 座標幾何、数直線、ベクトル、関数の形、物理配置。

次の場合は可視化**しない**: 散文や単一の式がすでに運べるとき。隣の文を繰り返すだけの装飾図はノイズと間違いの機会を増やす。迷ったらやらない — ない絵は偽の絵より安い。

## makerの選択

2人のmaker。`~/.agents/agents/` に役割定義がある:

- **`mermaid-maker`** — 構造・関係の絵: 依存グラフ、フローチャート、シーケンス/状態/ER/クラス図、木、マインドマップ、タイムライン。デフォルトで、依存グラフの教授法に直接合う。
- **`svg-maker`** — Mermaidがレイアウトできない空間・幾何の絵: 正確な座標、幾何図形、数直線、ベクトル、プロット、カスタム形状。

原則: ノードとエッジ/関係なら mermaid-maker。位置と形/幾何なら svg-maker。

## makerをよくブリーフする: 1つのアイデア、最小要素

最も多い失敗は**詰め込み** — 余分なラベルごとに絵が読みにくく、レイアウトも難しくなる。ブリーフ前に最小の要素に刈り、それぞれに問え: *「これを消したらアイデアはまだ明確か?」* なら消せ。

makerには概念**と**具体的な要素を与えよ — 曖昧なトピックでも長いチェックリストでもない。

- BAD: 「TCPがどう動くかの図を作って」
- GOOD: 「graph TD: 上にノード'packet'; 下へ'ordering'と'retransmit on loss'への矢印; 両方から下へ'reliable stream'。タイトルなし。信頼性がパケット*から*築かれることを示す（パケットの横に並ぶのではなく）」

アイデアは保ちつつ構成はmakerに任せ; ブリーフが5〜7要素超えたら先に削れ。

## 呼び出し（herdr委譲）

makerを起動してブリーフを送る（構文は orchestrate / herdr スキルに従う）:

1. 自分のロール名を確認・設定（`herdr agent rename "$HERDR_PANE_ID" <ロール>`、未設定なら）
2. `herdr tab create --workspace "$HERDR_WORKSPACE_ID" --label viz-<トピック> --cwd <プロジェクト>` → pane分割・ラベル付け
3. `herdr agent start mermaid-maker|svg-maker --kind pi --pane <pane-id> --timeout 60000` — **画像対応モデルで起動する**（PNGを目で検証するため）
4. 依頼プロンプト = `~/.agents/agents/<maker>.md` の本文 + ブリーフ + 完了報告の定型句:

```
完了したら、この pane のシェルで以下を実行してから終了してください:
herdr agent prompt <自分のロール名> "完了報告: filename=... path=..."
```

5. 完了報告を待つ。makerは `RESULT: filename/path` または `RESULT: NONE` で返す。

`RESULT: NONE` なら、正しい絵を作れなかった。ブリーフを単純化・再考するか、絵が不要と判断する。自分で図を手書き・偽造するな — 正確性はmakerのrender-and-inspectループに依存する。

## レッスンに埋め込む

ナレーションの参照でなく、Obsidianのwikilink埋め込みを教えるレスポンスに直接置け。**返されたファイル名**（フルパスでなく）と表示幅を使う:

```
![[viz-<slug>-<timestamp>.png|500]]
```

これだけで済む。`md-log`拡張はレスポンス本文をリンクされた.mdにそのままミラーし、Obsidianは保管庫内のどこでもファイル名で埋め込みを解決する（makerはプロジェクトの`viz`フォルダへ保存し、これは保管庫内）— レッスン内に自動で描画される。幅`|500`が良いデフォルト。込み入った図はより大きく。絵を一文で紹介し、絵にアイデアを運ばせよ — すべての要素を散文で語り返すな。

## なぜこれが信頼できるか

- makerは**見ていない絵を返さない**。だから「レンダリングはできるが偽のことを言う」が学習者に届く前に捕捉される。
- PNG埋め込みは**makerが検証したものと学習者が見るものがピクセル単位で同一** — 再レンダリングによるずれがない。
- ユニークなファイル名でObsidianのファイル名解決の曖昧さを排除する。

> makerのレンダリングは拡張 `visual-tools-svg.ts` / `visual-tools-mermaid.ts` が提供するツール（write_svg/edit_svg/render_svg、write_mermaid/edit_mermaid/render_mermaid）で行う。Mermaidはグローバルにインストールされた `@mermaid-js/mermaid-cli`（mmdc）+ Chrome、SVGは `rsvg-convert`（フォールバック `magick`）。自分でレンダリングしない — ブリーフしてファイル名を埋め込むだけ。
