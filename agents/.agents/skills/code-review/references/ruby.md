# Ruby / Rails の基準

本人の過去レビュー指示（toypo-api）から抽出。

- **標準機構に乗せる**: 自前のエラーハンドリングより `create!` 等で raise させる。`find` は存在しなければ raise するのだから自前の `find_xxx` + `render_bad_request` は不要。条件は `validate ..., if:` で素直に表現する（メソッド名に unless を入れない）。
- **ActiveRecord で書けるものは AR で**: 生SQLや手続き的な絞り込みの前に scope / AR のメソッドで書けないか確認する。`rank?` のような述語メソッドが既に生えていないかも確認する。
- **定数・知識はドメイン側（モデル）へ**: セパレーター等の知識を builder や runner に持たせない。呼び出し側が定数群を知っているのは配置ミス。
- **Runner / Job は呼ぶだけ**: 実行役にレポート生成やコマンドライン組み立て等を持たせない。責務が増えたら役割ごとにクラスを分ける。
- **賢すぎるインターフェース禁止**: 受け取ったオブジェクトの内部（`csv.errors` 等）を勝手に覗かない。検証は検証されるデータ側（Row 等）に寄せる。出力（puts 等）を業務ロジックに混ぜない。
- **外から呼ばれないメソッドは private に**。
- **依存の注入・テスト容易性**: 差し替えたい外部（API・時間・DB・乱数）は注入で受け取り、外から差し替えられる境界を作る。クラスメソッドやグローバル直呼びの連鎖はテストを難しくする。生Hashのまま解釈を読み手に委ねず、値オブジェクト等で意味を明示する。
- **テスト**: 価値のあるところだけ。let と it の交互連打で読みにくくするくらいなら context で分ける。AIによる大幅修正に耐えるため、細かいロジックテストよりブラックボックスE2E（it 1つでも可）を優先する。
