# 注釈の中身

文章はすべて `$essence` に従う。結論ファースト、1文1情報、事実ベース、ノイズ排除。

## 実データ

変数に実際に入る値を、リポジトリの実ファイル構成・schema・fixture・設定から特定する（創作しない）。不明なら安全なコマンドで確認する。パスは実行環境の配置で書く。
`ex` は必ずこのリポジトリで実際に流れる値。机上の創作例は不可。

## カード（what / ex / ref）

- `what`: 正確な操作記述1〜2文。1文目が結論。
- `ex`: 実例（入力→出力）で腹落ちさせる。出力は評価値に限らず、そのコードが生む具体物（解決されるパス・発動するキー・作られるレコード等）でよい。
  - 多段パイプラインは最終出力だけでなく中間状態も示す。
  - 実例に一般則を1句添える（例だけだと読者が帰納の責任を負う）。文字クラス・パターン系は非ASCII境界例（日本語・空白）を1つ含める。
- `ref`: 公式リファレンスの該当セクションURL。確信があるURLのみ。うろ覚えなら公式トップに落とす。捏造URLは信頼を壊す。リンクだけでよい。読者が次に調べたいであろう箇所には多めでよい。

## 書き方のルール

- 1文1情報。短い文に分ける。
- わかりやすさのための言い換えで曖昧になるなら正確な方を取る（例: `:h` は「親ディレクトリを返す」ではなく「末尾のパス名要素を取り除く」）。
- コールバックや非同期APIは、呼び出し自体が返す値とコールバックに渡る値を分けて書く（戻り値を受けようとするのが定番の事故）。
- 紛らわしい構文は隣接する書き方との対比で（`'\t'` と `"\t"` は2文字のまま。タブになるのは `$'\t'` だけ）。順序に意味があるガードは、入れ替えたら何が壊れるかを1行で。
- スコープ境界の依存を明示する。対象外を指す識別子（コマンド名文字列・グローバル・他ファイル定義のキー等）は、定義元パスと不在時の失敗モードを⚠か既存カードの1文で。
- 変数が暗黙に生まれる場所（`read var`・コールバック引数・キャプチャ）は「ここで var が作られる」と注釈する。
- コメントや文字列中の他ファイル参照は、その正体を1行で解決する。
- 類推のダメ押し・由来・うんちくは書かない。
- 外部APIの注釈は全引数を列挙せず、この行の実引数での結果 ex 1行を優先する。

## trace（実データの書き込み）

データが形を変える行（ループ・代入・分岐）に、その時点の実値を書く。特に出どころが行より後ろにある構文（`while read` + `done < <(...)`・コールバック・遅延評価）では、ループ頭に「何が・何件・どこから」を必ず書き、出どころ行へ `ref` を付ける。目安は1関数に3〜5個。データの形が変わらない行には付けない。
trace は青マークで表示され、ホバーで内容、クリックで出どころ行へ飛べる。

## issues

実際に踏みうる問題だけ。`set -e` を足したら壊れる、のような重箱ネタは書かない。該当行の横に ⚠ カードとして出る。

## 警告レベル

基準は「主流言語の汎用知識だけで意味を推測できるか」。対象言語固有でない構文（POSIX/bash共通・C系共通）は下げる。迷ったら上に倒す。

- **L2 🔴**: 知らないと行の意味が推測できない、または見た目から想像する挙動と実際が乖離するもの。欄外カード。
  例: zsh `${(s:/:)v}` `*(N/)`、Ruby `&:sym`、Rails の暗黙マジック、TS `infer`・mapped type、Terraform `[*]`・`dynamic`、JS `Proxy`
- **L1 🟡**: 読めるが誤読や罠があるもの。ホバーで一言メモ。
  例: クォート有無で挙動が変わる、`-e` と `-L` の違い、JS `==`、Go `defer` の引数評価タイミング
- 汎用知識で読める行には何も付けない。目安: L2 は5〜15個/100行（短いファイルは比例）。
- 見た目は普通だが実行環境に接続された暗黙挙動（Neovim `vim.g`、Rails callback）も L2。
- 構文でなく引数の意味が推測不能な場合も対象。外部APIに渡す裸の `true`/`false`/`nil`/数値フラグは、何を切り替えるかを一言。

## 仕上げのセルフチェック

- 各注釈が読者が実際に質問したはずのことに答えているか。他の注釈で自明になったものは削る。
- 1画面（30行）に 🔴 や trace が4個以上並ぶ箇所は密度を疑う。🔴 は1機能あたり8〜9枚が目安。全事実が他の 🔴 + 相互参照1句で導出できるなら 🟡 へ降格。導出できない同系カードは1枚に統合。
- 不慣れな言語は L2 を厚めに `ref` 付きで。慣れた言語は注釈を絞り、`flow` と `issues` を充実させる。
- `fig` は言葉で伝わらない構造だけ（flow の箇条書きと同じ情報なら描かない）。1ファイルに0〜2個。
