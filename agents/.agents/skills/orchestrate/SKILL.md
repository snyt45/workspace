# サブエージェントへの委譲（herdr）

herdrの操作方法・構文・安全規則は herdr スキル（`herdr --skill`）に従う。このスキルは委譲の運用規約だけを定める。

## 実行前の確認

まずタスクを分解し、サブエージェントの数と役割分担は lead が設計して提案する。並列数は通常 1〜2、最大でも 4〜5（コストがかかるため。増やすのはタスクの独立性が高く並列の利得が明確なときだけ）。

起動する前に、以下を1メッセージの選択式で簡潔にユーザーへ確認する。配置は固定で、現在のworkspaceに新規タブを作る（右pane分割は使わない）:

1. **エージェント数**: 何体起動するか
2. **構成**: 各エージェントのロール名とハーネス（pi / claude）と使うモデル。タスクの重さ・適性・トークン効率で提案する。原因究明・設計レビューなど重いタスクは `fable`（Fable 5）や `opus`（Opus 5）を優先し、`sonnet`（Sonnet 5）は軽めの実装や確認作業向けにする
   - ハーネス: pi / claude から選ぶ（herdr の agent kind に合わせる）
   - claude ハーネスのモデル: `fable`（Fable 5）/ `opus`（Opus 5）/ `sonnet`（Sonnet 5）から選ぶ
   - pi ハーネスのモデル: provider は `opencode-go` を優先、無いモデルは `opencode`（zen）。モデルは `glm-5.2` / `deepseek-v4-flash`（どちらも1Mコンテキストで大きめ入力向き）/ `kimi-k2.6` / `kimi-k2.7-code`（コーディング向き、opencode-goのみ）から選ぶ
3. **依頼内容**: 各エージェントに送るプロンプトの一行要約

複数のサブエージェントに委譲する場合も、全員分の情報をまとめて1メッセージで確認する。承認を得てから起動する。

## 起動手順

1. **lead に名前を付ける**: `herdr agent rename "$HERDR_PANE_ID" lead`（`lead` が既に使われていたら `<project>-lead`）。以下これを「lead名」と呼ぶ。サブエージェントはこの名前で完了報告を送る
2. 新規タブ作成 → `agent start`（ロール名、`--timeout 60000`）→ 依頼プロンプト送信

## 依頼プロンプトの定型句

依頼プロンプトの末尾に必ず付ける（`<lead名>` は実際の名前に置換する）:

```
完了したら、この pane のシェルで以下を実行してから終了してください:
herdr agent prompt <lead名> "完了報告: <変更/調査の要約・検証結果・懸念点>"
（報告文に引用符は含めない。長文は一時ファイルに書いて、そのパスを送ってください）
```

**ユーザーが直接サブエージェントに指示する場合も同じ。** 指示の出し手が lead でなくても、サブエージェントには必ずこの定型句を入れる（報告は常に lead 名へ送らせ、lead が把握・回収・報告できるようにする）。

## 回収（プッシュ方式）

```
   lead(pi) ──agent prompt──▶ サブエージェント（依頼）
     ▲                            │ 完了
     │                            ▼
     └── agent prompt lead ◀── 報告（サブエージェントが実行）
          （piの入力として届き、自動でターン開始）
```

- lead は prompt 後ブロックせず、自分の作業を続けるかターンを終えてよい。完了報告は `herdr agent prompt` 経由で pi の入力として届き、**自動でターンが再開する**
- 報告が届いたら `agent read <名前>`（報告内のファイルパスがあればそれも確認）で最終出力を確認し、要約をユーザーへ報告する。報告が届いたターンで必ず報告まで完了させる
- 複数を並走させた場合は、報告が届いた順に処理する。特定の1体を待ち続けない
- 報告への返信はユーザーにのみ。サブエージェントへ自動返信しない（無限ループになる）。追加指示はユーザー確認後に既存エージェントへ `agent prompt` する

## フォールバック（報告が来ないとき）

サブエージェントがクラッシュした・定型句を守らなかった等で報告が届かない場合は、従来どおり pull で回収する:

- `agent list` で全体の状態を確認しながら、`wait`（`--timeout 60000` 程度で刻み）→ `read` で完了した順に回収して報告する
- `blocked`（承認・質問待ち）は read で状況を確認して解消する。放置しない

## 運用規約

- 新規タブで作業する。`herdr tab create` で作成し、**必ずタブ名を付ける**（例: `investigate-freeze`, `impl-checkin-fix`）。タブ名はタスク名ベースにしてサイドバーで分かるようにする
- 名前はロール名（reviewer, impl, tester…）。追加指示・回収はすべて名前で行う
- 名前は herdr セッション全体（全workspace横断）で一意。`agent_name_taken` になったらプロジェクト名や連番を付けて回避する（例: dotfiles-reviewer, reviewer2）
- 作成したpaneにも同じロール名のラベルを付ける（サイドバーで誰が何をしているか分かるように）
- prompt は `--wait` を付けず即戻る
- 並列で同一リポジトリへ書き込む場合は、起動前に worktree を分ける
- 回収・報告後も pane・タブは閉じずに残す（続きの指示や結果の確認に使える）。同じロールへの追加依頼は新規起動せず既存エージェントを再利用する
- 閉じるのは、不要になったことをユーザーに確認してから。自分が作った pane・タブだけを閉じる
- 起動タイムアウトは 60 秒に伸ばす。タイムアウト後も起動していることがあるので pane を確認し、生きていれば rename して続行する
