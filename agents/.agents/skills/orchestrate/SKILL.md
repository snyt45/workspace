# サブエージェントへの委譲（herdr）

herdrの操作・構文・安全規則は herdr スキル（`herdr --skill`）に従う。このスキルは委譲の運用規約だけを定める。

## 実行前の確認

タスクを分解し、サブエージェントの数と役割を lead が設計して提案する。並列数は通常1〜2、最大4〜5（コストがかかるため。増やすのはタスクの独立性が高く利得が明確なときだけ）。

起動前に以下を1メッセージの選択式でユーザーへ確認する:

1. **エージェント数**
2. **構成**: 各エージェントのロール名とハーネス（pi / claude）と使うモデル。
   通常タスク（画像が不要）はテキスト専用の安いモデルでよい。pi ハーネスのデフォルトは `deepseek-v4-flash`（$0.22/$0.66 per 1M）。claude ハーネスは `sonnet`（$2/$10・画像対応）。
   画像・スクリーンショットを読むタスクは低コストの画像対応モデルを使う: `gpt-5.6-luna`（$0.2/$1.2・1M context）か `mimo-v2.5`（$0.14/$0.28）。テキスト専用モデル（`deepseek-v4-flash` など）では画像が読めない。
   重いタスク（原因究明・設計レビュー・難易度の高い実装）は能力優先で引き上げる: pi は `kimi-k2.7-code`（$0.95/$4）、claude は `fable` / `opus`。
   画像対応可否は `input: ["text", "image"]` で判断。config は `~/.pi/agent/models-store.json` で確認する。
3. **依頼内容**: 各エージェントに送るプロンプトの一行要約

複数のサブエージェントに委譲する場合も、全員分をまとめて1メッセージで確認する。承認を得てから起動する。

## 起動手順

配置は固定で **1オーケストラ=1タブ、呼び出し元workspace内**。

1. **lead に名前を付ける**: `herdr agent rename "$HERDR_PANE_ID" lead`（既に使われていたら `<project>-lead`）。以下これを「lead名」と呼ぶ。サブエージェントはこの名前で完了報告を送る
2. 新規タブ作成 → タブ内のルートpaneを分割 → 各paneに `agent start`（ロール名、`--timeout 60000`）→ 依頼プロンプト送信

   タブ作成:
   ```
   herdr tab create --workspace "$HERDR_WORKSPACE_ID" --label <タスク名> --cwd <プロジェクト>
   ```
   `--workspace` を省略すると、UIでフォーカス中のworkspace（別プロジェクトのことが多い）にタブが作られる。作成応答の `tab.workspace_id` が `$HERDR_WORKSPACE_ID` と一致することを確認する。不一致なら閉じて作り直す。

   分割の配置指針: 横に広いpaneは right、縦に狭いpaneは down。同じ方向の連続分割で細くしすぎない。先に right で2列にしてから各列を down で割ると見やすい。

3. 各paneにロール名と同じラベルを付ける（サイドバーで誰が何をしているか分かるように）

名前は herdr セッション全体（全workspace横断）で一意。`agent_name_taken` になったらプロジェクト名や連番を付けて回避する。

## 依頼プロンプトの定型句

末尾に必ず付ける（`<lead名>` は実際の名前に置換）:

```
完了したら、この pane のシェルで以下を実行してから終了してください:
herdr agent prompt <lead名> "完了報告: <変更/調査の要約・検証結果・懸念点>"
（報告文に引用符は含めない。長文は一時ファイルに書いて、そのパスを送ってください）
```

指示の出し手が lead でなくても、サブエージェントには必ずこの定型句を入れる。報告は常に lead 名へ送らせ、lead が把握・回収・報告できるようにする。

## 回収（プッシュ方式）

```
   lead(pi) ──agent prompt──▶ サブエージェント（依頼）
     ▲                            │ 完了
     │                            ▼
     └── agent prompt lead ◀── 報告（サブエージェントが実行）
          （piの入力として届き、自動でターン開始）
```

- lead は prompt 後ブロックせず、自分の作業を続けてよい。完了報告は `herdr agent prompt` 経由で pi の入力として届き、自動でターンが再開する
- 報告が届いたら `agent read <名前>`（ファイルパスがあればそれも確認）で最終出力を確認し、要約をユーザーへ報告する。届いたターンで必ず完了させる
- 複数を並走させた場合は、届いた順に処理する。特定の1体を待ち続けない
- 報告への返信はユーザーにのみ。サブエージェントへ自動返信しない（無限ループになる）。追加指示はユーザー確認後に既存エージェントへ `agent prompt` する

## フォールバック（報告が来ないとき）

サブエージェントがクラッシュした・定型句を守らなかった等で報告が届かない場合は pull で回収する:

- `agent list` で全体状態を確認しながら、`wait`（`--timeout 60000` 程度で刻み）→ `read` で完了した順に回収して報告する
- `blocked`（承認・質問待ち）は read で状況を確認して解消する。放置しない

## その他の運用ルール

- 同一リポジトリへ並列書き込みする場合は、起動前に worktree を分ける
- 回収・報告後も pane・タブは閉じずに残す（続きの指示や確認に使える）。同じロールへの追加依頼は新規起動せず既存エージェントを再利用する
- 閉じるのは、不要になったことをユーザーに確認してから。自分が作った pane・タブだけを閉じる
- タイムアウト後も起動していることがあるので pane を確認し、生きていれば rename して続行する
