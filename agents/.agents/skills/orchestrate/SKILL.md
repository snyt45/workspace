# サブエージェントへの委譲（herdr）

herdrの操作方法・構文・安全規則は herdr スキル（`herdr --skill`）に従う。このスキルは委譲の運用規約だけを定める。

## 実行前の確認

まずタスクを分解し、サブエージェントの数と役割分担は lead が設計して提案する。並列数は通常 1〜2、最大でも 4〜5（コストがかかるため。増やすのはタスクの独立性が高く並列の利得が明確なときだけ）。

起動する前に、以下を1メッセージの選択式で簡潔にユーザーへ確認する:

1. **配置**: 現在のpaneの右分割 / 同一workspaceの新規タブ
2. **構成**: エージェント種別とモデル。タスクの重さ・適性・トークン効率で提案する
   - claude: `fable`（Fable 5）/ `opus`（Opus 5）/ `sonnet`（Sonnet 5）から選ぶ
   - pi: provider は `opencode-go` を優先、無いモデルは `opencode`（zen）。モデルは `glm-5.2` / `deepseek-v4-flash`（どちらも1Mコンテキストで大きめ入力向き）/ `kimi-k2.6` / `kimi-k2.7-code`（コーディング向き、opencode-goのみ）から選ぶ
3. **依頼内容**: 送るプロンプトの一行要約

複数のサブエージェントに委譲する場合も、全員分（それぞれの配置・構成・依頼内容）をまとめて1メッセージで確認する。承認を得てから起動する。

## 運用規約

- 名前はロール名（reviewer, impl, tester…）。追加指示・回収はすべて名前で行う
- 名前は herdr セッション全体（全workspace横断）で一意。`agent_name_taken` になったらプロジェクト名や連番を付けて回避する（例: dotfiles-reviewer, reviewer2）
- 作成した新規タブ・paneにも同じロール名のラベルを付ける（サイドバーで誰が何をしているか分かるように）
- prompt は `--wait` を付けず即戻る。lead はブロックせず自分の作業を続け、回収時に wait → read する
- 複数を並走させたら、特定の1体を待ち続けず `agent list` で全体の状態を確認しながら、完了した順に回収して報告する
- 自分の作業が尽きて回収待ちだけになったら、ターンを終えず wait で回収・報告まで完了させる（ターンを終えると自発的には再開できない。その間の監視は herdr-status の通知が担う）
- wait は `--timeout 60000` 程度で刻み、タイムアウトしたら状態を確認して繰り返す。長い単発 wait 中はユーザーの途中入力（steering）が届かないため、1分以内に反応できる粒度を保つ
- `blocked`（承認・質問待ち）は read で状況を確認して解消する。放置しない
- 並列で同一リポジトリへ書き込む場合は、起動前に worktree を分ける
- done / blocked を検知したら、結果の要約をユーザーへ報告する
- 回収・報告後も pane・タブは閉じずに残す（続きの指示や結果の確認に使える）。同じロールへの追加依頼は新規起動せず既存エージェントを再利用する
- 閉じるのは、不要になったことをユーザーに確認してから。自分が作った pane・タブだけを閉じる
- 起動タイムアウトは 60 秒に伸ばす。タイムアウト後も起動していることがあるので pane を確認し、生きていれば rename して続行する
