# Walkthrough

walkthroughは、コード上のポイント列（ステップ）を意図した順序で辿る1つの説明単位。各ステップは `file:line` と、その点が経路上にある理由の解説（note）を持つ。

## 形式

チャットに以下の形で出力する（JSONは生成しない、ファイル保存もしない）:

```markdown
## <概要タイトル>

1. `src/api.ts:6` — このポイントで何が成り立ち、何が次に起きるか
2. `src/api.ts:12` — 次のステップの解説
3. `src/main.ts:3` — エントリポイントの役割
```

- 1ステップ1論点。2つの考えが必要なら分割する
- noteは「なぜこの点が経路上にあるか」を語る。何の不変条件が成り立つか、どの仮定が誤っているか、次に何が起きるか
- 行番号は現在のHEAD側のもの。削除のみの変更は、その削除を参照している周辺の残存行に置く
- 並び順は意図で決める（実行順・diffの上から順・重要度順など）。競合パスは順序をnoteで明示する

## 委譲元

- diff理解 → `walkthrough-diff`
- レビュー指摘 → `walkthrough-review`
