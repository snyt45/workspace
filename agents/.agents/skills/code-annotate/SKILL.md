# Code Annotate（構文解説）

対象コードの引っかかりやすい構文を先回りして潰す。読者は経験のあるエンジニア。主流言語の汎用知識だけでは意味を推測できない行・誤読しやすい行が対象。

## 2つのモード

- **解説モード（デフォルト）** — 構文を教える依頼。下の手順でチャットに回答する。ファイル生成・plannotator 操作はしない
- **注入モード（明示指示のみ）** — 「注釈として注入して」「plannotator に付けて」と言われたときだけ `guides/inject.md` に従う

## 解説手順

1. **対象を読む** — 質問された行/範囲とその周辺を読む。実データ（fixture・schema・設定・実際の呼び出し元）をリポジトリから特定する（創作しない）
2. **構文を特定する** — 引っかかりどころを判定する。L2: 知らないと行の意味が推測できない / L1: 読めるが誤読や罠がある。基準は `guides/content.md`「警告レベル」
3. **答える** — `guides/content.md`「コード解説の組み立て」に従い、依頼に応じて必要なセクションだけを使う（結論 → 最小例 → 動き → なぜ → 比較 → メンタルモデル → 実践的慣習）
4. **レベルを明示する** — 重要な構文には「重要: …」または「注意: …」の1文を添える。汎用知識で読める行は「これは通常の書き方」とだけ言って深掘りしない

## 実データの原則

- 変数に実際に入る値を repo の実ファイル・fixture・設定から特定する。不明なら安全なコマンドで確認する
- 例は必ずそのリポジトリで実際に流れる値。机上の創作例は不可
- 1文1情報・結論ファースト・ノイズ排除（$essence）

## ファイル

- `guides/content.md` — 共通の中身の書き方（「コード解説の組み立て」＝メンター式構成、「注釈の中身」＝警告レベル判定・実データ・カード形式）
- `guides/inject.md` — 注入モード専用手順（plannotator の実差分へ注釈を置くとき。明示依頼時のみ）
