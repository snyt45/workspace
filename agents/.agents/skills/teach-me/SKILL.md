# teach-me

`teach` スキルに教授を移譲し、同時に `md-log` でセッションをファイルにミラーする。本スキルはオーケストレーションのみ。ファイル作成と md-log 開始を済ませた後、後は `teach` と `md-log` に任せる。

**制約:** md-log はチャットのテキスト出力をファイルに追記する。`render_mermaid` / `render_svg` で生成した PNG 画像は自動的にはファイルに含まれない。図は mermaid 記法ブロック（```mermaid）としてテキスト出力に含めるか、後で手動で貼り付ける必要がある。

## フロー

### 1. トピックを特定

引数または依頼文から教える対象トピックを特定する。曖昧な場合は確認する。

### 2. 保存先・ファイル名を決定

**デフォルトパス:**
```
/Users/snyt45/Library/Mobile Documents/iCloud~md~obsidian/Documents/pkm-vault/Learn
```

ユーザーに以下のように確認する:
> デフォルトの `Learn` フォルダに保存しますか？（Y / n / 別のパスを指定）

- `Y` または未入力 → デフォルトパスを使用
- `n` または別パス指定 → 指定されたパスを使用（存在しない場合は親ディレクトリを `mkdir -p` してから作成）

**ファイル名:**
トピックを英語に翻訳しスネークケースに変換、末尾に `.md` を付ける。既存と衝突したら `_2`、`_3` … を付ける。

例: `微分形式` → `differential_forms.md`

### 3. ファイルを作成

`write` ツールで作成。内容はトピックの見出しのみ:

```markdown
# {{元のトピック}}
```

**作成後、必ずファイルパスをユーザーに通知する:**
> ファイルを作成しました: `<フルパス>`

### 4. md-log を開始

ファイル作成後、ユーザーに以下のメッセージを表示し、手動での md-log 連携を促す:

> ファイルを作成しました: `<フルパス>`
>
> 以下のコマンドをチャットに入力して、md-log を開始してください:
> `/md-log <フルパス>`
>
> md-log を開始したら「開始しました」と教えてください。

ユーザーの確認を待ってからステップ5へ進む。

### 5. teach に移譲

ユーザーが md-log を開始したことを確認したら、`/skill:teach` で `teach` スキルを読み込み、教授を開始する。その指示に従う。

その後は `teach` スキルの Probe → Plan → Teach フローに従い、内容は md-log 連携先ファイルに自動追記される。
